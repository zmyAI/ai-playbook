# Git 通用约束

## 分支命名规范

- **新建 Git 仓库时，主分支统一使用 `main`，不使用 `master`**

## 提交前确认规范

- **提交前检查工作区未暂存修改**：`git status` 确认待提交文件，逐一 `git diff <file>` 对比暂存区与工作区版本，发现未暂存修改则提示用户确认是否纳入——避免 Agent 写入后用户手动编辑的内容被遗漏
- **执行 `git commit` 前，必须先向用户展示提交信息，获得确认后再提交**
- 不展示 diff 就直接 commit 视为违规操作

## 提交范围规范

- **只提交用户明确要求的文件**，不能把暂存区或其他未提及的修改一并提交
- 用户说"提交暂存区修改"或"提交 xx 仓库修改"时，先判断是否可拆分为多个独立提交；如认为应该拆分，主动询问用户
- 严禁将用户未提及的变更混入提交

## 提交信息规范

- **首次提交规范**：新建仓库时首次提交，提交信息固定为 "Initial commit"
- **基于实际变更编写**：提交前须执行 `git diff --staged` 确认实际变更，并据此编写提交信息
- **格式要求**：提交信息包含中文逗号或空格时，用管道方式提交：`echo 提交信息|git commit -F -`，Windows shell 下 `-m "..."` 会保留双引号到提交信息中
- **语言规范**：提交信息应全部使用中文（英文项目除外），以简洁的动词+内容格式为主
- **技能要求**：提交信息要符合**git-commit-helper**技能要求

## 推送规范

- **不要自动推送**，除非用户明确说明"提交并推送"或"push"
- 默认行为：仅 commit，不 push
- 只有用户明确要求推送时，才执行 push 操作
