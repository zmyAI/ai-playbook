# 文章发布流水线 (Article Review Pipeline)

利用 git 作为流转记录，通过独立 Agent 实现客观审稿。

## 触发词

发布流程、文章流水线、审稿、过审、走流水线、开始写文章、帮我写公众号

## 全局规则

- **每次审稿必须使用独立 Agent 执行**（非当前对话的主 AI），避免自己审自己
- **每次审稿必须传入 `review-rubric.md` 作为参考标准**
- **用户说"通过"时，必须提醒："文章已通过审稿，请提交 git 后继续。"**
- 不新建目录，不创建 JSON 状态文件——git commit 就是状态
- round 计数靠口头记录，原稿最多 3 轮，卡兹克优化最多 2 轮

## 流程

### 阶段 1：原稿

1. 用户给素材/选题/想法
2. AI 根据选题判断 HKR 质量：H（有趣/悬念）、K（知识密度）、R（共鸣感），至少过 2/3 才能进入写作
3. 写出原稿，保存到 `source/原稿/`
4. 提示用户："原稿已写好，请 review 并提交 git。"
5. 用户提交后，AI 审稿（见审稿标准 L1+L1a+L2+L3+L4）
6. 输出修改建议，用户修改后提交
7. 独立 Agent 再次审稿，重复至多 3 轮
8. 用户说"通过"时提醒提交，然后进入阶段 2

### 阶段 2：发布准备

1. 将原稿复制到 `source/_posts/`，确保 frontmatter 正确（title、date、author、tags、summary）
2. 提示用户提交
3. 确认后复制到 `source/文章写作模板/已发布/`（如有该目录）作为存档

### 阶段 3：卡兹克优化

1. 调用 khazix-writer 技能对 `_posts/` 中的文章进行风格优化
2. 用户 review diff，修改后提交
3. AI 审稿（审稿标准 L1-L4 严格版 + L5 优化效果验证），最多 2 轮
4. 用户说"通过"时提醒提交

### 阶段 4：封面 & 发布

1. 调用 wechat-cover-skill 生成封面（3 张可选）
2. 用户挑选最佳版本
3. 调用 wechat-post-html 转换为公众号 HTML
4. 更新飞书待办状态（调用 topic-publish-tracker 协议）
5. 发布到公众号

## 审稿执行协议

每轮审稿的执行步骤：

1. 读取待审文件
2. 使用独立 Agent 执行审稿，prompt 中：
   - 说明审稿角色（你不是作者，是独立审稿人）
   - 附带 `review-rubric.md` 全文作为参考
   - 要求输出结构化审稿报告
3. 将审稿报告交给用户
4. 用户决定修改或说"通过"

## 输出格式

每次审稿报告必须包含：

```markdown
### 审稿报告 — 第 N 轮

#### L1 硬性规则
- [ ] L1-1 违禁词：通过/不通过（问题列表）
- [ ] L1-2 违禁标点：通过/不通过（问题列表）
- [ ] L1-3 结构八股：通过/不通过（问题列表）
- [ ] L1-4 模糊工具名：通过/不通过（问题列表）

#### L2 风格一致性
- [ ] 开场：通过/不通过
- [ ] 节奏：通过/不通过
- [ ] 口语化：通过/不通过
- [ ] 标点复核：通过/不通过

#### L3 内容质量
- [ ] 观点支撑：通过/不通过
- [ ] 知识输出：通过/不通过
- [ ] 文化升华：通过/不通过
- [ ] 对立观点共情：通过/不通过

#### L4 活人感
- [ ] 温度：通过/不通过
- [ ] 独特性：通过/不通过
- [ ] 立场：通过/不通过
- [ ] 流畅度：通过/不通过

#### 本轮总结
- 通过项：X/Y
- 未通过项及修改建议（按优先级排序）
```
