# WeChat Cover Skill V3（公众号封面图生成）

## 简介

基于火山引擎 SeeDream 模型（`doubao-seedream-5.0-lite`）为公众号文章生成封面图，自动裁切至 2.35:1 并生成 1:1 缩略图。

## 核心理念（V3 重构，2026-09-29）

**封面图是氛围视觉，不是信息图。文字交给公众号编辑器，不交给生图模型。**

V2 及更早版本的最大错误：让生图模型渲染精确中文标题、标签、按钮、窗口样式——这是生图模型最不擅长的事。结果字写错、版式僵硬、像 PPT 模板。

V3 彻底改变：
- **封面图去文字化**：prompt 中**禁止**出现任何要求渲染文字的内容（标题、副标题、标签、公众号名都不画）
- **标题文字由公众号编辑器承担**：公众号列表页/详情页本来就会显示标题，不需要画进封面
- **prompt 从"版式说明"改为"风格描述"**：描述氛围、色调、视觉隐喻、主体意象，让模型自由构图
- **构图唯一要求**：主体居中、上下留裁切余量——仅此而已

判断标准：一张好的封面，放大后没有任何文字也能传达文章的气质和主题。

## 使用方式

### 生成封面图

当用户提及"配封面图"、"生成封面"、"配图"等触发词时：

1. **读取文章内容**，提炼核心意象：
   - 文章在讲什么（主题）
   - 文章的情绪基调（兴奋/冷静/批判/好奇……）
   - 最核心的视觉隐喻（一个画面：什么物体、什么光线、什么氛围）
2. **设计视觉方向**（1-2 个候选）：
   - 风格关键词：赛博朋克 / 极简 / 抽象 / 超现实 / 像素艺术 / 水墨 / 霓虹 / 蒸汽波 / 手绘插画……
   - 色调：冷色科技感 / 暖色治愈感 / 黑白极简 / 高饱和撞色……
   - 主体意象：一个能与文章主题产生隐喻联系的视觉主体（如"反向信息悖论"→ 数据漩涡中的单人剪影）
   - 如果拿不准，向用户提供 1-2 个方案方向让其确认
3. **编写 prompt 并调用脚本**：按下方"V3 prompt 编写规范"写提示词，传入 `--prompt`
4. **展示结果**：显示生成的四个文件路径（原图、2.35:1 裁切图、1:1 缩略图、prompt 文本）
5. **保存 prompt**：prompt 文本自动写入同目录下的 `cover_prompt.txt`，方便排查图片与 prompt 的对应关系
6. **更新文章**：在合适位置添加 `![封面图](文章目录/cover.png)`

### 生成文章总结卡

当用户提及"总结卡"、"课代表总结"、"文章总结图"时：

1. **读取文章内容**，提炼核心观点和关键模块
2. **设计竖版信息图**（1080×1920，适合手机阅读）
3. **编写 prompt 并调用脚本**：传 `--size 1080x1920 --basename summary`
4. **脚本处理**：四周 8% 裁切

> 总结卡与封面不同，它本质是信息图，需要文字承载内容——此场景保留文字渲染要求，但也应精简文字数量。

## V3 prompt 编写规范（AI 编写 prompt 时必读）

### 封面图（2640×1404）

**结构模板（按此组织 prompt）：**

```
公众号封面图，尺寸2640x1404。
【风格】<风格关键词 + 具体描述，如：赛博朋克、霓虹夜色、深蓝与洋红对比>
【主体】<一个与文章主题形成隐喻的视觉主体，描述其形态、材质、光线>
【氛围】<色调、光影、环境细节、情绪基调>
【构图】主体居中偏上，上下边缘各留约10%的安全余量，重要视觉元素不要贴边。
【禁忌】画面中禁止出现任何文字、字母、数字、logo、水印。
```

**硬性规则：**

1. **禁止文字**：prompt 中不得出现「标题是……」「标注……」「文字……」「标签……」「写着……」等任何要求渲染文字的描述。画面出现文字即失败。
2. **禁止版式**：不得要求"左右分栏""窗口样式""按钮""对话框"等 UI 版式——那是信息图的做法，不是封面。
3. **禁止品牌图标**：不渲染具体产品的 logo/图标，用抽象视觉元素代替。
4. **主体隐喻**：封面必须有一个"视觉锚点"（一个物体/一个场景/一个意象），不能是纯背景纹理。这个锚点要与文章主题有隐喻关联，而不是把文章标题翻译成画面。
5. **氛围优先**：多用氛围词（夜色、晨光、数据流、金属质感、雾气、光晕、噪点），少用功能词（"科技感""高级感"这种抽象形容词无效，要描述具体画面）。
6. **色彩具体**：给具体色相或搭配（深蓝到深黑渐变、洋红霓虹、暖黄羊皮纸），不给"好看的颜色"这种抽象描述。

**好 prompt 示例（V3）：**

```
公众号封面图，尺寸2640x1404。
【风格】赛博朋克数字夜景，深蓝与洋红霓虹对比，高对比度，电影感光影。
【主体】一个半透明的人形剪影坐在巨大显示器前，显示器中涌出金色数据流，数据流化作丝带缠绕向画面四周延伸。
【氛围】深色背景点缀星点光斑，微弱雾气，整体氛围冷静而略带不安，象征"你的输入正在被学习"。
【构图】主体居中偏上，上下边缘各留约10%的安全余量，重要视觉元素不要贴边。
【禁忌】画面中禁止出现任何文字、字母、数字、logo、水印。
```

（此示例对应"AI 时代信息不对称"类主题，实际生成时根据文章内容替换主体意象与氛围。）

### 总结卡（1080×1920）

- 保留文字渲染，但**精简文字数量**：只保留标题、3-5 个模块标题、每模块 1-2 句要点
- 四周 8% 为安全区，文字不贴边
- 明确告诉模型每个文字内容是什么（而非占位符）

- 用户明确指定某风格时使用
- 直接要求"用之前的风格"时使用

但**不默认使用**——每次生成优先根据文章内容动态设计。所有模板均遵循 V3 规范（无文字、风格描述、主体隐喻）。

## 尺寸与裁切（脚本自动处理，prompt 无需关心精确像素）

- 封面生成尺寸：**2640×1404**（约 1.88:1），裁切后为 **2.35:1**（2640×1123）
- 总结卡生成尺寸：**1080×1920**（竖版），四周 8% 裁切
- 缩略图：从裁切图的 2.35:1 画面中心裁切 **1:1** 正方形（1123×1123）
- **prompt 只需写"主体居中、上下留约10%安全余量"，精确裁切由脚本完成**

## 上传封面到公众号后台（2026-10-30 跑通，browser-use-automation plane="bu"）

封面图在本地生成后，需要灌录到公众号草稿作为封面。完整可靠链路如下。

### 前置条件

- 本地已有封面图（建议 2.35:1，3140×1335 左右），路径为绝对路径
- 公众号后台已登录，拿到当前 `token`（首页 URL 里的 token 参数）
- 目标草稿的 `appmsgid`（草稿箱卡片 DOM `data-appid` 属性）
- 编辑页 URL 模板：`https://mp.weixin.qq.com/cgi-bin/appmsg?t=media/appmsg_edit&action=edit&type=77&appmsgid={appmsgid}&token={token}&lang=zh_CN`

### 完整步骤（每步附可直接运行的 bu 代码）

```python
import seed_browser_use as bu
import time

# 1. 导航到编辑页
bu.navigate(edit_url)
time.sleep(3)

# 2. 直接 JS 点「从图片库选择」打开素材库对话框
#    （不用先点封面区弹菜单，菜单项 .js_imagedialog 始终在 DOM 里）
bu.js("document.querySelector('.js_imagedialog').click()")
time.sleep(2)

# 3. 上传本地封面到素材库
#    上传控件是对话框内隐藏的 file input，accept 含 image
bu.upload_file("input[type=file][accept*='image']", r"D:\path\to\cover.jpg")
time.sleep(4)

# 4. 切到「最近使用」分组（新上传的图排最前）
bu.js("""
document.querySelectorAll('a').forEach(a => {
  if (a.textContent.includes('最近使用')) a.click();
});
""")
time.sleep(2)

# 5. 选中第一张图（刚上传的）
#    选中成功标志：图片项出现绿色边框
bu.js("""
const items = document.querySelectorAll('.weui-desktop-img-picker__item');
if (items.length > 0) items[0].click();
""")
time.sleep(1)

# 6. 点「下一步」进入「编辑封面」对话框（等 1-2 秒，按钮选中态才刷新）
bu.js("""
const btns = document.querySelectorAll('a, button');
for (const b of btns) {
  if (b.textContent.trim() === '下一步' && b.offsetParent !== null) { b.click(); break; }
}
""")
time.sleep(2)
# 此时截图应看到「编辑封面」标题 + 2.35:1 裁切框

# 7.【关键】「确认」按钮必须用户手动点（自动化点击无效，对话框会关但封面不提交）
#    调 interaction.request_action(type="browserControl") 请用户点确认

# 8. 用户点完确认后，【立即】保存草稿，绝对不要刷新/导航页面
bu.js("""
const btns = document.querySelectorAll('a, button');
for (const b of btns) {
  if (b.textContent.trim().includes('保存为草稿') && b.offsetParent !== null) { b.click(); break; }
}
""")
time.sleep(3)
# 成功标志：页面出现绿色 toast「已保存」，封面缩略图显示在封面区
```

### 关键坑（血泪教训）

1. **「确认」按钮自动化无效**：JS click / bu.click(ref) / click_xy 都能让对话框关闭，但封面不会提交。**必须用户手动点**。
2. **用户点完确认后绝对不能刷新或导航**：封面设置在内存里，一刷新就丢（2026-10-30 Figma 稿第一次因此白跑）。确认后第一件事就是点「保存为草稿」。
3. **不要先点封面区弹菜单**：菜单可能弹不出来（会话级失效），直接 JS 点 `.js_imagedialog` 更可靠。
4. **上传成功验证**：素材库分组计数 +1（如「最近使用」71→72、「我的图片」52→53）。
5. **选中图片用 `.weui-desktop-img-picker__item`**：点文件名 div 或图片缩略图本身都可能不触发选中，点这个 class 的容器才出绿框。
6. **「下一步」要等 1-2 秒**：刚选中就点下一步经常无效，等选中态刷新后再点。
7. **保存后验证**：绿色「已保存」toast + 封面缩略图显示，两个都看到才算成功。草稿箱列表卡片有封面图是最终验证。

| 操作 | 选择器 / 代码 |
